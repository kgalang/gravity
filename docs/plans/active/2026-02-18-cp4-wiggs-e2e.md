# CP4 Plan (End-to-End Wiggs Responses)

Status: active
Owner: kevin + codex
Last Updated: 2026-02-18

## Goal
Ship an end-to-end Claude-backed Wiggs agent loop that can answer real DuckDB business questions in Slack.

## Scope Decision
CP4 is where we decide and implement the Claude loop dependency strategy: either pull `pi-coding-agent` (+ required `pi-*` packages) or continue with Gravity-native loop wiring. CP4 includes this decision explicitly before deeper runtime integration.

### Dependency Decision (2026-02-18)
Use the `pi-*` dependency path and align CP4 runtime dependencies with `@mariozechner/pi-mom@0.52.12` package contracts.

Selected dependency set for CP4:
- `@mariozechner/pi-agent-core@^0.52.12`
- `@mariozechner/pi-ai@^0.52.12`
- `@mariozechner/pi-coding-agent@^0.52.12`
- `@anthropic-ai/sandbox-runtime@^0.0.16`
- `@sinclair/typebox@^0.34.0`
- `chalk@^5.6.2`
- `croner@^9.1.0`
- `diff@^8.0.2`

Notes:
- Keep existing Slack dependencies (`@slack/socket-mode`, `@slack/web-api`) and Postgres dependencies (`kysely`, `pg`) in place.
- Pin `@mariozechner/pi-*` packages to a single matching version line to avoid cross-package API drift.
- Initial CP4 model target for Wiggs is `claude-opus-4-6` (via `pi-ai` model resolver).

## CP4 In/Out
- In scope: Claude API loop, per-turn skill loading from `store/`, DuckDB query capability through skills/tooling, response formatting for Slack, and tool output truncation protections.
- Out of scope: full session manager/compaction system (CP6), session/memory reliability test matrix (CP7), scheduler/heartbeat behavior (CP10).

## Risks
- Claude API credentials/model configuration may be incomplete.
- Dependency choice (`pi-*` vs native) can alter implementation speed and rollback complexity.
- DuckDB CLI/path assumptions may differ across environments.
- Large tool outputs can still degrade response quality without strict truncation limits.

## Exit Criteria
- `/wiggs` answers real business questions from DuckDB in Slack with consistent formatting.
- Skills are loaded from `store/` on every turn.
- Truncation behavior prevents oversized tool outputs from breaking the loop.
- `npm run check` passes.
- Docs and checkpoint state are updated in the same change.
