# CP4 Plan (End-to-End Wiggs Responses)

Status: complete
Owner: kevin + codex
Last Updated: 2026-02-18

## Goal
Ship an end-to-end Claude-backed Wiggs agent loop that can answer real DuckDB business questions in Slack.

## Scope Decision
CP4 is where we decide and implement the Claude loop dependency strategy: either pull `pi-coding-agent` (+ required `pi-*` packages) or continue with Gravity-native loop wiring. CP4 includes this decision explicitly before deeper runtime integration.

## Checkpoint Sequencing Note (2026-02-18)
- Checkpoint IDs remain canonical (`CP1` through `CP11`) as defined in `mvp_requirements.md`; no renumbering.
- A CP10 foundation slice (proactive scheduler + Slack proactive delivery wiring) was intentionally pulled into CP4 to de-risk end-to-end runtime integration.
- CP4 exits first; CP10 is marked complete only after CP10-specific validation work (live trigger validation, replay/backfill behavior, manual wake tooling, and quiet-hours behavior).

### Dependency Decision (2026-02-18)

Notes:

- Initial Wiggs target model remains `claude-opus-4-6` (set on the `gravity.agents.model` column).

## CP4 In/Out
- In scope: Claude API loop, per-turn skill loading from `store/`, DuckDB query capability through skills/tooling, response formatting for Slack, tool output truncation protections, and ingress-binding-driven Slack trigger handling (slash + app mention + thread/DM message).
- Out of scope: full session manager/compaction system (CP6), session/memory reliability test matrix (CP7), proactive trigger live validation/hardening work (CP10 completion pass), and `npm run doctor` runtime checks (tracked as tech debt for post-CP4 follow-up).

## Risks
- Claude API credentials/model configuration may be incomplete.
- Dependency choice (`pi-*` vs native) can alter implementation speed and rollback complexity.
- DuckDB CLI/path assumptions may differ across environments.
- Binding misconfiguration can cause over-triggering or missed triggers when non-slash paths are enabled.
- Large tool outputs can still degrade response quality without strict truncation limits.

## Exit Criteria
- `/wiggs` answers real business questions from DuckDB in Slack with consistent formatting.
- Ingress-binding-driven non-slash triggers behave correctly for mention/thread/DM paths.
- Skills are loaded from `store/` on every turn.
- Truncation behavior prevents oversized tool outputs from breaking the loop.
- Model selection for a run is unambiguous (`gravity.agents.model` only).
- `npm run check` passes.
- Docs and checkpoint state are updated in the same change.
